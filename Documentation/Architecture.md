# Architecture decision: Ciao 4

Ciao uses Swift 6 language mode with Sendable values and actors for application-visible ownership. The tools minimum is Swift 6.0. Deployment targets are iOS 18, tvOS 18, and macOS 15: a consistent Swift 6-era baseline that supports Synchronization in deterministic tests. Validation uses Xcode 27.0 / Swift 6.4. No public API is main-actor isolated.

Network.framework owns normal discovery and listener-backed advertising. Its mature NWBrowser/NWListener APIs support the selected deployment baseline; the newer structured Network APIs in the Xcode 27 SDK are not required by this package. DNS-SD owns external-port registration, independent SRV/TXT resolution plus address lookup, and type enumeration. Ciao never makes an NWConnection to resolve a service. DNS-SD symbols are exported by libSystem; no third-party dependency or extra dns_sd library is needed.

DNSOperation is the only `@unchecked Sendable` wrapper. Its serial dispatch queue confines every mutable field, raw reference, callback, TXT update, and reference deallocation. DNSServiceSetDispatchQueue delivers callbacks on that queue. Unretained callback contexts remain valid until synchronous queue-draining teardown. Stop is idempotent. Deallocation on the queue avoids callback-after-free; deinit checks its dispatch-specific key to avoid synchronously dispatching onto itself.

DiscoverySession consumes backend snapshots serially, emits removals before additions, and tracks automatic resolver tasks by identity and generation. Removed services cannot receive late resolution events. Identity includes name, normalized type/domain, and interface index. A service visible on multiple interfaces therefore has multiple identities. Current membership clears on stop; a browser's subsequent search is a fresh session. A Network waiting or failed state terminates the stream with a diagnostic, including permission failures; individual resolution failure is an event associated with its service.

Discovery events use unbounded buffering to preserve membership. Consume promptly and stop long-running sessions. One consumer owns each stream. Cancelling iteration stops the session. A plain break does not imply cancellation: call session.stop() explicitly after an early exit. Actor teardown also cancels outstanding resources.

CiaoServer.events reports startup, stopping, and failures after publication, and a backend failure clears publishedService. CiaoServer replaces any previous publication when start is called again. Generation checks prevent a cancelled or superseded startup from committing late success. Start checks cancellation before allocating resources and after startup. Timeouts race work against a cancellable Task.sleep; cancellation tears down the backend. External mode requires a nonzero caller-owned port; listener mode permits zero and reports the actual selected port. The listener rejects incoming connections because Ciao does not implement an application protocol. Applications needing accepted connections should own their listener and use external-port advertising.

TXT records retain binary values and distinguish flag, empty value, and absent key. Keys are ASCII, case insensitive, and normalized to lowercase. Every encoded entry must fit in 255 bytes; total record length must fit the DNS-SD 16-bit API. Empty records use one zero-length string. Resolution returns the first completed available address batch with numeric IPv4/IPv6 addresses, including IPv6 zone identifiers when applicable; it is a snapshot, not continuing address/TXT monitoring.

Logging is no longer globally mutable. Callers receive typed errors and events and can route them into their own concurrency-safe logger. DNS-SD errors retain their native numeric codes; Network errors retain descriptive diagnostics.
